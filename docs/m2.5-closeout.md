## Architecture and simplification

The crate boundaries still match the [product plan](plan.md#architecture).
The core crate owns the provider contract, engine events, tools interface, and session format.
The provider crate implements adapters.
The binary connects those pieces to both interfaces.
The TUI owns display state and sends user actions through its driver.
The mock crate serves tests and benchmarks; it does not ship in the binary.

The review found no speculative abstraction or unused config key that requires removal now.
The new dependencies are `pulldown-cmark` for Markdown and `log` for execution traces.
The theme's `status_bar` key remains useful on small screens without an input frame.

Five provider capability flags remain unread by production consumers.
Only `tool_calls` controls engine behavior.
The existing [M3 decision](plan.md#providers-neutral-by-construction) retains the other flags until M3 close-out.
Remove each flag that still lacks a consumer at that point.

### Measurements that decide further changes

The transcript keeps layouts after their blocks leave the viewport.
Browse mode walks all blocks below the viewport to keep the top row in place.
The [transcript](../crates/demerzel-tui/src/transcript.rs) and [renderer](../crates/demerzel-tui/src/render.rs) implement that behavior.
A fast redraw at the transcript's end does not measure this browse cost.

The new Mac render receipt covers these cases; Linux confirmation remains pending:

1. Measure a cached browse frame at 400 and 2,000 blocks.
2. Measure card expansion and collapse separately while the view sits near the top.
3. Render the whole history before measuring retained layouts in follow mode.
4. Measure a width change and a filled editor.

A replay's first frame lays out only the visible tail.
It cannot establish the memory cost after a user browses the whole history.
The current retained-buffer helper counts text, rendered text, row indexes, and face arrays.
It excludes card bodies, thinking summaries, other indexes, and temporary allocations.
Process memory and retained-buffer counts therefore need separate labels.
The plan's approximate cache bound also excludes row-index storage and unused allocation capacity.

## Contract growth since M2

The six contract families below describe the implementation at the review revision.
They supplement the metrics script's name counts.

### Provider contract

The `Provider` methods remain `id`, `capabilities`, and `stream`.
The stream event variants remain unchanged.
`Request` adds `effort: Option<Effort>`.
The neutral effort levels are `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`, and `ultra`.
The [provider contract](../crates/demerzel-core/src/provider.rs) defines these types.

### Engine events

`EngineEvent` adds `ReasoningEnd {}`.
`ToolEnd` adds a borrowed `output` field.
`ToolStart`, `ToolRun`, and `ToolEnd` gain `#[non_exhaustive]`.
The [engine](../crates/demerzel-core/src/engine.rs) defines these events.

### Tool names and input schemas

The six tools remain `read`, `edit`, `create`, `bash`, `grep`, and `glob`.
Their input schemas remain unchanged.

### Config keys

The config parser adds these keys:

| Scope | Added keys |
| --- | --- |
| Top level | `effort`, `max_model_calls` |
| `providers.<id>` | `effort`, `context_window` |
| `tui` | `mouse`, `markdown`, `thinking`, `theme` |
| `theme.<name>` | `text`, `dim`, `accent`, `error`, `success`, `warning`, `heading`, `link`, `inline_code`, `code_block`, `prompt`, `status_bar`, `progress_line`, `diff_add`, `diff_remove`, `keyword`, `string`, `comment`, `number` |

The environment also gains `DEMERZEL_EFFORT` and `DEMERZEL_LOG`.
These environment variables are not config-file keys.
The [config reference](config.md) describes their values and precedence.

### Session file schema

The schema version remains 1.
The [session records](../crates/demerzel-core/src/session.rs) gain these fields:

| Record | Added fields |
| --- | --- |
| `meta` | Optional `effort` and `approval` |
| `usage` | Optional `at` and `duration_ms` |
| `turn` | Optional `at` and `duration_ms` |
| New `tool` record | `call_id`, `name`, `at`, `duration_ms`, `is_error`, `output_bytes`, `truncated` |

The Rust `Usage` variant changes from a tuple variant to a struct variant.
Its JSON token fields remain flat.
Older records without the optional fields still load.

### CLI flags and subcommands

The CLI adds `--session` and `--effort`.
The `doctor` and `login` subcommands remain unchanged.
The shared command registry also adds `/session`, `/effort`, and `/approval`.
