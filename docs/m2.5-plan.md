# M2.5 Implementation Plan — Interface Build-out

This plan turns the M2.5 milestone of [`plan.md`](plan.md) into ordered,
verifiable steps. It follows the shape of [`m2-plan.md`](m2-plan.md).

## Status (2026-08-22)

The M2 build order is complete (PR #27) and the M2 close-out ran on
2026-08-23: the alignment review found the repository aligned with
[`plan.md`](plan.md), and the macOS metrics receipt is committed. The
Linux metrics receipt lands as a follow-up when the Linux reference

milestone ([`bench-platforms.md`](bench-platforms.md)).

## Goal

After M2.5, the full-screen interface is the way to use Demerzel. It
renders model output as formatted text with highlighted code. Thinking
is a block the user can open and close. Each tool call is a card with
its input, status, duration, and output. A progress line shows the
live model call. The input takes several lines and completes commands.
Colors come from a theme. The plain REPL stays as the low-dependency
fallback with its M2 behavior.

## Exit criteria

M2.5 is done when all of these hold:

1. A dogfood session in this repo through the TUI shows every
   element, and a scripted PTY scenario covers each one:
   - formatted model text with highlighted code fences;
   - thinking blocks that open and close;
   - tool cards with status, duration, and an output tail;
   - the progress line during a model call;
   - the status bar.
2. Multi-line input and slash-command completion work in the PTY
   suite. The Ctrl-C rules hold at every point. `--plain` behaves as
   in M2.
3. Two built-in themes and one config-defined theme render in PTY
   scenarios. `NO_COLOR` and a 256-color terminal degrade without
   error.
4. The render bench on a formatted transcript: one redraw at 120x40
   under 1 ms, and `stream` above 1,000 frames per second. Boot to
   prompt and idle memory stay within 10% of each machine's M2-era
   receipts, on both reference machines
   ([`bench-platforms.md`](bench-platforms.md)). The stripped binary
   stays inside the 15 MB M2.5 budget after the highlighter lands,
   with a `cargo-bloat` receipt. Size is a budget, not a wall: the
   receipt can justify a crossing, function never gets cut for size.
5. `cargo fmt`, `cargo clippy`, `cargo test`, and `cargo doc` are
   clean. The metrics receipt is committed at the close-out.

## Workspace after M2.5

No new crate. `demerzel-tui` gains modules for the block transcript,
markdown, highlighting, cards, the editor, and themes. `bench/render`
gains a formatted-transcript fixture.

```text
crates/demerzel-tui/src/
  transcript.rs   # blocks with a layout cache (rewritten)
  markdown.rs     # markdown events to styled rows (new)
  highlight.rs    # code fences to styled rows (new)

  editor.rs       # multi-line input, completion (replaces input.rs)
  theme.rs        # roles, built-in themes, color depth (new)

```

## Design

### The block transcript (demerzel-tui)

Today the transcript stores logical lines with a kind, and the
renderer wraps the visible tail. M2.5 stores blocks:

- `Text`: the markdown source of one model reply segment, streamed.
- `Reasoning`: the readable summary, an open flag, a live flag.
- `Tool`: the call id, the name, the driver's preview, the state, the
  start and end times, the output tail, an expanded flag.
- `Notice`, `Error`, `Prompt`: one line each, as today.

Each block owns a layout cache: its styled rows at the last width. A
width change or a change to the block invalidates the cache. The
renderer walks blocks from the bottom until the viewport is full, so a
long session pays for its window, not its history. Streaming touches
only the open block, so one frame costs that block's re-layout plus
the viewport walk.

Caps carry over: a block count cap replaces the line cap, and a
per-block byte cap bounds the re-layout of the open block.

Follow mode: the view sticks to the bottom until the user scrolls up.
A scroll up enters browse mode and shows an indicator with the count
of new rows below. `End` returns to follow mode. The mouse wheel
scrolls. Mouse capture is on by default, and the `mouse` config key
turns it off: capture takes the terminal's own text selection on some
terminals, and Shift-drag keeps it on most.

### Markdown rendering

`pulldown-cmark` parses a `Text` block into events. A renderer in this
crate maps the events to styled rows:

- headings, emphasis, and inline code;
- lists with indent and markers, block quotes, and rules;
- links as text with a dim URL;
- tables cut to the viewport width;
- fenced code with a frame and a language label.

The open block re-parses on each frame that changes it. The parse is
linear in the block, and the byte cap bounds it. A fence that is not
closed yet renders as code from its opening line, because the stream
is mid-fence.

Rows wrap at display width with the existing wrap rules. Code rows
wrap too, so every character stays on screen. A `markdown` config key
turns the rendering off and shows the raw text, for copying.

### Syntax highlighting

The candidate is `syntect` with its default syntax set, loaded on the
first code fence and never on the boot path. Step 4 decides it with a
`cargo-bloat` receipt against the 15 MB budget. The fallback is a
small built-in highlighter with keyword, string, comment, and number
classes for a fixed set: Rust, Python, JavaScript and TypeScript, Go,
shell, JSON, TOML, YAML, Markdown. Either way, the theme maps a small
set of highlight classes to colors.

### Tool cards and the progress line

One card per tool call:

- Header: the tool name, a one-line input summary from the driver's
  preview, and a state glyph.
- Body: the preview — the diff for an edit, the command for bash —
  capped as in M2.
- Footer: the duration, the tool's one-line summary, and an output
  tail of a fixed row count. A key expands the tail to the capped
  full output.

States: pending approval, running, done, error, declined, interrupted.
The approval question stays on the input row; the card shows that it
waits. The interface measures the duration between `ToolRun` and
`ToolEnd`.

Engine-event growth: `ToolEnd` gains the tool's output text, borrowed.
The interface caps what it keeps. Today the event carries only the
one-line summary, and the card's output tail needs the text.

The progress line is one row above the input while a model call
runs. It shows a spinner, the elapsed time, and the phase: thinking,
writing, or the running tool's name. It hides at idle. The status bar
keeps the session totals.

### Thinking blocks

One `Reasoning` block per reasoning segment. Closed by default: the
first line of the summary with a live indicator while deltas arrive,
then the elapsed time. A key opens and closes the newest block. A
`thinking` config key sets the default: `closed`, `open`, or
`hidden`. Engine-event growth: a reasoning-end event, because today
only `ReasoningDelta` reaches the sink and a block has no boundary.

### The input editor

The editor holds several lines. Alt-Enter inserts a newline; Enter
submits. Shift-Enter inserts a newline too when the terminal reports
it through the keyboard-enhancement flags. Pasted newlines stay. The
box grows to a fixed row count and scrolls inside it. Cursor movement
works across lines, and the M2 kill keys carry over.

Typing `/` opens a completion popup with the command registry: usage
and help per command. Tab and the arrow keys select; Enter completes.
The registry stays in the binary crate; the interface receives the
list through its options, so M3 custom commands extend the same list.

### Theming

A theme maps named roles to colors. The roles:

- text, dim, accent, error, success, warning;
- heading, link, inline code, code block;
- prompt, the status bar, the card frame, the progress line;
- diff add and diff remove;
- the highlight classes.

Three themes ship: `terminal`, the M2 default that sets no colors;
`dark`; and `light`. Config picks one and can define more:

```toml
[tui]
theme = "dark"
markdown = true
thinking = "closed"
mouse = true

[theme.ocean]
accent = "#5fafd7"
error = "#ff5f5f"
```

Truecolor applies when the terminal declares it; a 256-color terminal
gets the nearest palette entry; `NO_COLOR` sets no colors. A project
file can set these keys: they are cosmetic and cannot raise privilege.

### The first-run screen

When no provider credential resolves, the interface shows one screen
before the prompt. It holds the logo, the credential state per
provider from the doctor probe, and the login commands. Enter
continues to the session, where a turn fails with the clear
credential error until a login lands. The cross-harness credential import — the jcode
first-run design target in the project notes — waits for M3
discovery.

### Measurement

The render bench gains a formatted-transcript fixture: markdown with
headings, lists, tables, and code fences, plus cards and a thinking
block. `frame`, `ingest`, and `stream` run on it, and a `reflow`
bench measures a width change. Exit criterion 4 names the gates. PTY
scenarios cover each element; a resize forces the full repaint the
frame diff otherwise skips, the step-6 lesson.

## Dependencies

Each new dependency passes a `cargo-bloat` check against the 15 MB
M2.5 budget and the 25 MB budget
([`bench-platforms.md`](bench-platforms.md)). Dev-only crates are
exempt.

| Crate | Purpose |
|---|---|
| pulldown-cmark (no default features) | markdown parsing |
| syntect (candidate, decided in step 4) | syntax highlighting |

Not added: a ratatui markdown widget crate, an image protocol crate,
a custom terminal renderer. The markdown renderer lives here so
streaming and the theme stay in one place.

   multi-line paste and a completed command.*

## Decisions to make during M2.5

- The REPL — decided now. Presentation work is TUI-only. The REPL
  keeps its M2 behavior, the shared engine events, and the shared
  command registry. Parity tests cover the events and the commands,
  not the look.
- The highlighter — step 4, with the bloat receipt.
- Mouse capture default — step 2. On, with the `mouse` key off for
  terminals where capture blocks selection.
- Code rows: wrap or cut — step 3. The plan says wrap; the dogfood
  confirms it.
- Thinking default state — step 6. The plan says closed.
- Shift-Enter through the keyboard-enhancement flags — step 7, by
  terminal support; Alt-Enter is the portable path.
- Reverse history search (Ctrl-R) — step 7, after dogfood.
- `ToolEnd` output: the full text borrowed, the interface caps — the
  plan's shape; step 5 confirms it against the bench.
- The theme config shape — step 8. `[tui] theme` plus
  `[theme.<name>]` tables, as above.

## Risks

- **Binary size from the highlighter.** Mitigation: the bloat receipt
  decides; the fallback highlighter is small.
- **Frame cost from re-parsing markdown.** Mitigation: the layout
  cache; only the open block re-lays out; the byte cap bounds it; the
  render bench gate.
- **Reflow on resize.** Mitigation: the cache is keyed by width and
  only the visible blocks re-lay out.
- **Terminal compatibility.** Keyboard enhancement, mouse capture, and
  color depth differ across terminals. Mitigation: a named fallback
  per item; the PTY suite runs with and without each feature.
- **Two interfaces drift.** Accepted by design: the REPL is the
  fallback. The shared events and the registry keep the behavior one.
- **Scope creep.** The exit criteria are the fence. Panes, images, and
  a palette stay out.
