## macOS receipt run

Connect mains power before the run.
Keep Low Power Mode off and the thermal state nominal.
Stop builds and other heavy work before timing starts.
Use a clean checkout after the measurement changes land.
Run these commands from the repository root:

```bash
cargo build --release --locked
python3 bench/machine.py
bench/boot/run.sh
python3 bench/boot/pty_probe.py
python3 bench/boot/pty_probe.py --plain
python3 bench/memory/idle.py
bench/render/run.sh
bench/turn/run.sh
python3 bench/boot/pty_probe.py --cold-system
cargo build --release --locked
python3 bench/metrics.py
```

Keep the system-cold run last among timing runs because it purges the system disk cache.
It needs macOS administrator authorization and produces a separate baseline.
The existing macOS boot target applies to warm startup.
The system-cold mode does not inherit a calibrated latency gate.

Collect the production size breakdown in a separate build directory:

```bash
cargo bloat --release --locked -p demerzel --bin demerzel --crates --message-format json --target-dir target/m25-bloat > target/m25-bloat.json
```

This command uses `cargo-bloat` 0.12.1.
The tool keeps symbols for analysis, so its file size differs from the stripped production binary.
Record the stripped size from `target/release/demerzel` separately.
Wrap the size breakdown with the measured revision, machine reference, tool version, and command before committing it.
